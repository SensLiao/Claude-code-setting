## Method (differs from README's interactive procedure — recorded for honesty)

Nine fresh **headless** sessions, one per fixture, prompt passed verbatim:

```
claude.exe -p "<fixture>" --output-format stream-json --verbose      (cwd = ../routing-test)
```

Driver: `run-fixtures.js` (session-scratch, not committed). It streams the events and kills the
child the moment the routing question is answered — first `Skill`/`Agent` tool_use (= the route),
or a mutating tool (= it went inline), or the `result` event. This caps token spend.

- The ledger's earlier planned `--max-turns 2` **no longer exists** in CLI 2.1.220; the kill-on-first-route
  rule replaces it.
- A first attempt capped the run after 3 tool calls of any kind and mis-scored fixture 1 as a miss
  (it explores with `Bash`/`Glob` *before* routing). Read-only exploration must not end the run.
  That attempt was discarded and fixture 1 re-run.
- Headless is a real main-loop session and exposes the same skill set (`init` event: 173 skills in
  every run, none of the six skills under test absent).

## Reading of the misses

- **The two that fired are exactly the two widened in `e76290c`** (GSD + UIUX). That is direct
  evidence the trigger-widening method works, and that QA / AppSec / L12 have not had it yet.
- **Failure mode is "competent inline instead of routed", not wrong domain.** Every missed fixture
  got a substantively correct domain answer — fixture 3 even reproduced a real auth bypass in the
  target's `login/route.ts` empirically. Nothing was mis-routed to another mainline.
- **Confound, stated honestly:** the target repo is 5 files, and fixture 3's session said so
  explicitly ("scope is tiny and self-contained … direct read-only review — no agents, no workflow").
  Part of the miss may be a size judgment rather than a trigger gap. It is not a blanket size effect
  though: fixtures 1 and 4 fired on the same 5-file repo.
- Negative fixtures (8, 9) and the manual gate (5) all held — **zero over-trigger**. The
  `claude-env-bootstrap` manual-first gate behaved exactly as designed, unprompted.

## Rounds 2 and 3 — trigger widening applied, then challenged

**Round 2** (QA + AppSec + L12 descriptions widened: English situational phrasing + a "small scope
does not waive this route" clause). Re-ran 2/3/6/7 — **only fixture 3 flipped** to
`Skill:appsec-security-orchestrator`. What worked there was naming the concrete loss from inlining
("no evidence trail, no ASVS / CSF mapping, no remediation routing"); QA's and L12's softer versions
did not move. All three missed sessions rendered a §0.6 plan-preview card and then did the domain work
themselves — the model treats showing a plan as discharging the orchestration duty. All three also
stalled on a missing precondition ("there is no login page", "nothing is published yet").

**Round 3** (QA + L12 only; copied AppSec's proven shape and added "a missing precondition is an
INPUT to this orchestrator, never a reason to answer inline"). Re-ran 2/6/7 — **2 and 7 flipped**,
6 still missed. Cumulative if every change is kept: 8/9 correct.

### …and that is the problem

Fixture 7 fired the orchestrator as its **very first tool call**, having read nothing — pure keyword
match, no judgment. The round-3 clause works precisely because it *removes* the model's ability to
decline on the grounds that there is nothing to work on yet. That manufactures over-trigger, which is
what fixtures 8 and 9 exist to prevent.

## Round 5 — the 1024-char authoring cap, and a methodology correction

Two caps exist, and this work-line only knew about the looser one:

| cap | value | enforced by |
|---|---|---|
| platform skill-listing truncation | 1,536 chars | `tests/harness/frontmatter-health.test.js` |
| **Agent Skills authoring spec** | **1,024 chars** | `tools/relocation-integrity/lint.js` G2 (watched skills) |

The widened AppSec description came in at 1,153 — under 1,536, over 1,024 — and turned
`relocation-integrity.test.js` from PASS to FAIL. Trimmed to 999 by deleting the self-dispatch
mechanism sentence (body detail, not routing signal) and one duplicate trigger phrase; the
anti-inline clause, the trigger vocabulary and the no-active-scans safety line were kept. A
full-library scan found no other description over 1,024. Harness is back to 13 PASS / 3 FAIL /
2 ERROR (the 3+2 are the pre-existing failures recorded in ledger [ctx-5], unrelated).

### n=1 is not a measurement

The first run of fixture 3 after that trim came back `(none)` — which read as "the trim broke the
one win". Three repeat runs at the identical wording all routed correctly: **fixture 3 is 3/4 at
999 chars**. The single miss was noise.

Routing is a probabilistic decision, and **every per-round verdict above was a single run**. They
are observations, not measurements. What that does and does not change:

- **Unaffected** — anything with a mechanical cause: the visibility probes (`DESCRIPTION-PRESENT`
  vs `NAME-ONLY` is deterministic given a settings state), the 1,024-cap violation, the harness
  results, and the name-only budget-reclamation experiment (control-verified, and the effect was
  4-for-4 on distinct skills).
- **Downgraded to single observations** — every fixture score in rounds 1-4, including "round 2
  flipped only fixture 3", "round 3 flipped 2 and 7", and the final 6/9. The *direction* of round 3
  is still supported by its mechanism (fixture 7 firing on tool call #1 having read nothing is not
  a coin flip), but the counts are not.
- **Not yet re-measured** — fixtures 1, 2, 4, 5, 6, 7, 8, 9 remain n=1 under the final wording.

Any future re-run of this fixture set should be **n≥3 per fixture** and report a hit rate, not a
binary. Repeating all 9 at n=3 is 27 headless sessions.
